## Class select screen (the "choose a class" step after PLAY)

Finished the step the brief puts between the lobby and the match: when the host presses START,
both machines now land on a Valorant-style lock-in grid before the buy phase opens.

**The phase machine gained a state.** `MatchState.ClassSelect` now sits between match start and
`BuyPhase`: `BeginMatch()` -> `EnterClassSelect()` -> (both lock, or the timer) -> `EnterBuyPhase()`.
It is a real phase, so the existing plumbing carries it for free — the host pushes it with the
same `SendPhase`, the client adopts it with the same `SetRemoteState`, `MatchHud` names it, and
`LoadoutUI` stays closed because it only opens on `IsBuyPhase`. Adding the state at the END of
the enum keeps the ordinals stable for the wire (the int is only ever exchanged between
identical builds anyway, but appending costs nothing).

**Lock state lives on `GameManager`:** `_classPick[2]` / `_classLocked[2]`, plus
`LockClass(slot, index)`, `HoverClass(slot, index)`, `GetClassPick`, `IsClassLocked`.
`LockClass` applies the class to the body **only when the slot is One** — the other player's
body is a network proxy whose real Health and abilities live on its owner's machine. Only the
host advances on a double-lock (`!RemoteAuthoritative`); a client sends its lock and waits for
the phase to arrive. Timer-out calls `AutoLockRemaining`, which assigns whatever the player was
hovering (falling back to random) — that is why a click records through `HoverClass` rather than
staying a UI-local variable. Offline, slot Two is the dummy and auto-locks instantly
(`!LobbyNetwork.IsActive`), so the screen never waits on nobody.

**New wire message `MsgClassLock`** (`t="lock"`, index, locked), routed through
`LobbyNetwork.OnClassLock` -> `NetMatchSync.HandleClassLock`. The slot mapping is the same both
ways: an incoming lock is always slot Two on this machine, whichever of us is hosting, so the
handler does not need to know the role.

**`ClassSelectUI`** — code-built overlay like the shop: 29 cards in four role-tinted columns,
hover previews a detail plate (name / role / traits / the kit with keys), click points, LOCK IN
commits, Enter works too, and two chips show what each player is on. Derived entirely from
`GameManager` state + a `_focusedIndex` for the hover.

**`forceRepickEachRound` flipped to 0 in the scene.** A class is now chosen per match, which is
what the brief asks. Weapon persistence between rounds is unaffected: `ApplyLoadoutReset` calls
`WeaponManager.ResetPurchases` on arrival at the buy phase, and that already re-equips
defaults, so only the class re-pick was lost — exactly the intent. The shop's class column is
now display-only once a match has started (locked tint, `[LOCKED]`), and still works as a
fallback if the select screen somehow got skipped.

## The nesting bug this exposed: `Time.timeScale` handoff

The select screen and the shop both freeze the match and hand off to each other on the same
frame (select closes the moment the buy phase opens). Each UI capturing and restoring
`Time.timeScale` itself breaks that: whichever opened that frame captures the 0 the other had
not restored yet, and the match stays frozen after the shop later closes.

**Fix: `MatchUiPause`** — one static depth counter. `Push()` remembers the time scale on first
in and zeroes it; `Pop()` restores it on last out. Both UIs use it. `ClassAbilityHost`'s
"don't fire abilities while a menu is up" guard now reads `MatchUiPause.IsPaused` instead of
`LoadoutUI.IsOpenNow`, so it covers both screens and any future one.

Also armed against the ordering being wrong in the first place: `ClassSelectUI` opens/closes by
*polling* the phase in `Update` like the shop does, so it can never open in the same handler
that closes the shop — and the shared counter makes that ordering irrelevant anyway.

## Valorant movement (Task #23) — slide cut, values retuned

The old `PlayerController` was arena-fighter feel: slide on Shift, walk 5.0, crouch 1.15,
deceleration 20. Valorant's gunplay movement is the opposite — brisk, repeatable peaks and
near-instant stops — so the slide went and the numbers moved.

- **Slide deleted entirely** (5 fields, `IsSliding`, `_slidePressed`/`_slideTimer`/
  `_slideDirection`, the start/steer branches, the Shift read). Nothing outside
  `PlayerController` referenced it.
- **Retuned**: `moveSpeed` 5.4 (knife-out speed), `crouchSpeed` 3.0 (~55%), `jumpHeight` 1.0,
  `acceleration` 16, **`deceleration` 90** (a full-speed stop in ~0.06s — that is the Valorant
  "stop and shoot" feel), `airControl` 0.45 (a jump can be curved, not reversed),
  `crouchTransitionSpeed` 14. Scene YAML updated by hand to match; the `MatchPreset`
  superSpeed tooltip no longer mentions stacking a slide.
- Kept the camera-feel layer (bob / strafe lean / landing dip / eased crouch eye height) and
  the "no jump while crouched" rule.

**Deliberately NOT added:** Shift-walk (Valorant's silent slow walk) and per-weapon move speed.
`OnFootstep` has no audio subscriber and there is no movement-inaccuracy model, so a slow-walk
key would do nothing; weapons have no speed field either. Both are candidate follow-ups.

## Seven compile errors the user screenshotted — all fixed

The user sent two error screenshots. I cannot see images, so I read
`C:/Users/bib/AppData/Local/Unity/Editor/Editor.log` instead (grep -anE "error CS[0-9]+";
the file is binary-flagged by grep, so `-a` is required). It held **7 distinct errors**, all
real, none from the movement work — the previous session's "0 error CS" read was wrong (it
only looked at the log TAIL; the compile block sat mid-log with 4800 lines of editor noise
after it. **Lesson: grep the whole log, not the tail.**)

1. **CS0246 x10 — `MovementAbilities` / `BodyAbilities` / `OffenseAbilities` in
   `ClassAbilityHost`** — these are NESTED namespaces
   (`ProjectLEA.Manuel.Abilities.OffenseAbilities`), and they were being written as
   `OffenseAbilities.MineAbility`. **Two wrong fixes before the right one.** First I added
   `using ProjectLEA.Manuel.Abilities.OffenseAbilities;` etc. — did nothing. A using imports
   the TYPES in a namespace, not the namespace's NAME as a prefix; the leaf is only usable as
   a prefix when it is *reachable* (top-level, or nested in the file's own namespace or an
   enclosing one). The fix is to import the namespace and write the **bare type name**:
   `typeof(MineAbility)`, not `typeof(OffenseAbilities.MineAbility)`.
2. **CS0104 x2 — `'Object' is ambiguous` in `AbilityArchetype`** — that file has
   `using System;`, so `Object` could be `System.Object` or `UnityEngine.Object`. Qualified
   as `UnityEngine.Object` at both sites. (Files WITHOUT `using System;` can use bare `Object`
   fine — `OffenseAbilities` does.)
3. **CS1061 x2 — `'Transform' does not contain 'main'` in `AbilityAim`** — a property named
   `Camera` shadowed `Camera.main` inside its own body, so the body read the property back.
   Renamed the property to `CameraTransform`. **This one cost a second round-trip:** I updated
   the property and both *external* callers but missed the three `var origin = Camera;` sites
   inside the same file, which then bound to the engine `Camera` TYPE and threw CS0119 +
   CS1061. Lesson: after renaming a public member, grep its name across the whole repo, and
   expect the declaration file itself to contain its own call sites.
4. **CS0103 — `HandleDetonate` in `OffenseAbilities`** — the method is `HandleDetonation`;
   the `+=` used the truncated name. (Only the `-=` was reported; both were wrong.)
5. **CS1503 — `NetMatchSync` spike relay** — `SpikeManager.OnStateChanged` is
   `Action<SpikeState, PlayerSlot, float>` but `SendSpike` takes an int planter. Cast
   `(int)planter` at the call site.
6. **CS7036 — `GameManager.EndRound()`** — `RoundManager.EndRound(PlayerSlot winner)` needs the
   winner; passed `winner` from the enclosing method's parameter.

**Verification hardening, check 6c in `verify_scripts.py`:** 6b strips every dotted name
(`[\w.]*\.[A-Z]\w*` -> " ") before its token scan, so a partially-qualified
`OffenseAbilities.MineAbility` never reached the check at all. New pass 6c walks the dotted
names instead: a brace-depth scanner reconstructs fully-qualified nested namespace names, then
flags `Leaf.X` whose namespace is not *reachable* (top-level, or nested in the file's own
namespace or an enclosing one). The first version of 6c had the same misconception I did — it
accepted the reference if the namespace was imported, which is exactly the case that is still
a CS0246. Corrected, then proven by injecting the broken pattern back in (3 FAILs), removing
it (clean). Also ran throwaway sweeps for the other two bug classes (event `+=`/`-=` naming a
method that does not exist; `Object.`/`Random.` in files with `using System;`) — clean.
