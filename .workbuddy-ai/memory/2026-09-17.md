# 2026-09-17

## Settings slider bug — finally found it

**Symptom:** clicking the *middle* of the "Master volume" bar set it to full. Clicking the
letter "m" in the label also grabbed the slider. Reported twice, my first fix did nothing.

**Two separate bugs, both in `SettingsMenu`:**

1. **Value mapping was off by half a bar.** `ApplySliderFromPointer` computed
   `t = (local.x + width*0.5f) / width`. That formula assumes local x runs `-w/2..+w/2`, which
   is only true when the pivot is 0.5. The track is built with `pivot = (0, 0.5)`, so local x
   actually runs `0..w` — and the pointer at the left edge already read t=0.5, at the middle
   it read t=1.0. **Fix:** divide by `rect.xMin`-anchored distance, which is pivot-independent:
   `t = (local.x - r.xMin) / r.width`.

2. **The drag started on the whole row.** `HandleSliderDrag` hit-tested `slider.Row`, a 920px
   strip, while the bar is only 380px. So clicking the label grabbed the slider and the
   row-relative press mapped to a wildly wrong value. **Fix:** added an invisible `Touch` rect
   over the bar (bar width + `touchPadding` each side, full row height, no Image so it does
   not draw) and drags now start only on that.

**Lesson:** when a UI hit test and a value mapping disagree, the bug looks like "the value is
wrong" but the cause is the hit area. Check both before touching the math.

## Local multiplayer — no packages, raw sockets

**Requirement:** two players on the same internet connection find each other and join. No
Relay, no Photon, no netcode package in `manifest.json` (only `com.unity.multiplayer.center`,
which is a wizard, not a transport).

**Architecture — `Assets/Scripts/Manuel/Net/`:**

| File | Role |
|---|---|
| `LobbyNetwork` | UDP broadcast/listen for discovery + TCP host/client, length-prefixed JSON |
| `NetMessages` | Wire messages. `MsgKind.t` tag first, then deserialise into the concrete class — `JsonUtility` has no polymorphism |
| `LobbyUI` | The PLAY screen tree: Root → Join/Create → preset pick → lobby → host START |
| `NetMatchSync` | Bridge between the socket and the managers. Host = authoritative, client = `RemoteAuthoritative` |
| `NetPlayer` / `NetProxyPlayer` | Local player ships its transform at 20 Hz; remote body catches up to it |
| `NetMatchBootstrap` | `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` — adds `NetMatchSync` only when a session is live, so the scene still works offline |
| `MatchPreset` | ScriptableObject game mode; `Standard.asset` lives in `Assets/Resources/Manuel/Presets/` |

**Host-authoritative, and the client owns nothing but its own avatar.** The host runs the
phase machine and pushes `phase`/`score` messages. The client's `GameManager` gets
`RemoteAuthoritative = true` so its own `Update` never advances a phase, and
`RegisterDeath` returns early — a client resolving its own kill would desync the two machines.
The client reports hits as `damage` (applied to the victim's real Health on the victim's
machine) and deaths as `death` (resolved by the host).

**Slot mapping is per-machine, not global.** Slot One always means "the player on this
machine" and slot Two means "the other one's body". On the host that IS the authoritative
model. On a client the host's slot Two means the client, so `HandleScore` flips the two slots
on arrival. Same reason `SetRemoteScore` raises no events — it is a paint job, not a decision.

**Client money gotcha:** the host does not know what the client spent in the buy phase, so a
money sync would silently refund it. `_clientLocalSpend` tracks locally-spent credits and
re-applies them on top of every authoritative value.

**Bug I caught before it shipped:** `LobbyNetwork.Awake` did `DontDestroyOnLoad(gameObject)`
while the component was being added to the MainMenu object — which would have carried the
menu, the settings panel and the lobby UI into the match scene. The session now owns a
dedicated `LobbyNetwork` root object, and `LobbyUI` reuses `LobbyNetwork.Instance` if a
session survived a previous match rather than orphaning a dead socket.

## Compile errors in the new net code — fixed

The screenshot showed the Console failing to build `Assembly-CSharp.dll`. Four real issues:

1. **`LobbyUI`'s nested `enum Screen` shadowed `UnityEngine.Screen`** → CS0117 at every
   `Screen.width`/`Screen.height` (6 sites). Renamed the enum to `LobbyScreen` and updated
   all use sites. Cleaner than qualifying each `UnityEngine.Screen` reference.
2. **`UdpClient.SendAsync(bytes, endpoint)`** → CS1503. Unity's class library has no
   `(byte[], IPEndPoint)` overload, only `(byte[], int)` and `(byte[], int, IPEndPoint)`.
   Fixed with `SendAsync(bytes, bytes.Length, endpoint)`. The synchronous `Receive(ref from)`
   in the same file was already the correct overload.
3. **CS0414 warnings**: `MainMenuUI.matchSceneName` (dead since PLAY now opens the lobby —
   `LobbyUI` owns the scene name) and `LobbyUI._hosting` (never read; `_net.IsHost` is used).
   Both fields deleted, plus the stale `matchSceneName: Manuel` line in `MainMenu.unity`.
4. `Tools/verify_scripts.py` passed despite errors 1 and 2 — it did no type-resolution work
   at all. Added a check that flags any local `class/struct/enum/interface` declaration whose
   name is in a small set of engine types used statically (`Screen`, `Time`, `Input`, ...).
   It caught the shadow immediately once armed.

### GOTCHA: parallel Edit calls on the same file silently clobber each other
Sending several `Edit` calls in one message for ONE file races — each writes the whole file
from a snapshot taken before the others landed, so the last write wins and quietly reverts
its siblings. Symptom: mixed states where some renames stuck and others vanished, with every
edit reporting success. The wrecked state was worse than the original: use sites said
`LobbyScreen` while the enum declaration still said `Screen`. **Rule: one Edit per file per
message, or use `Write` once.** Verify rename sweeps with a `Grep` for the old token after.

### Layout bugs found while the file would not build

`AddLabel(parent, text, position, size, ...)` anchors at `(0.5, 1)` with pivot `(0.5, 1)`,
so **`position` is an offset from the parent's top-CENTRE, not its top-left corner.** Every
row helper had hand-picked constants that were right for a left-anchored convention, so the
name text floated mid-row and overlapped the value/switch. Repositioned all of `AddStep`
(name at `-140`, arrows at `+70`/`+245`, value box at `+160`), `AddToggle` (name at `-4`,
description at `-28`, ON/OFF at `+108` left of the track), `AddRow` (both labels placed from
the row's own edges via `-width*0.5 + pad`, so one call works at 560 and 820), and the
lobby-entry rows.

Vertical overflow too: the left column held 12 rows + 2 headings and ran to -1030, through
the HOST/BACK buttons at -880. **ECONOMY moved to the right column under the cheats**; the
panel is now 1300x1060 with the glow plate and header rule following it via new `_glow` /
`_headerRule` fields (they were hard-coded to the 980x820 standard panel and would have
framed nothing on the wide screen).

## Multiplayer: opponents invisible, plus name, chat and scoreboard

Report: "we are not in the same area, I couldn't see my opponent." Three real bugs, all in
the avatar relay — the connection itself was fine.

1. **`LobbyNetwork.OnTransform` was raised but NOTHING subscribed to it.** `NetMatchSync`
   wired phase/score/damage/death but never the transform, so `NetProxyPlayer.ApplySnapshot`
   was never called and the opponent's body stood at its spawn forever. Added
   `HandleTransform` that looks up slot Two and hands the snapshot to its proxy.
2. **Both bodies ended up on the same spawn point.** Each machine runs the same scene with
   the same "slot One = me" mapping, so the client's real body and the host's body both
   stood on slot One's spawn. Fix: `RoundManager.LocalPlayerUsesRemoteSpawn` — on a client,
   `Respawn` mirrors BOTH slots (own body -> slot Two's point, host's proxy -> slot One's),
   which makes the two machines agree on every world position and stops the proxy being
   dragged across the arena at each round start.
3. **Hits on the opponent's proxy were applied to a throwaway local Health.** `SendDamage`
   and `HandleDamage` existed but nothing called the former. `WeaponUser` now relays via
   `TryRelayRemoteHit` when the target Health has a `NetProxyPlayer` up the hierarchy —
   direct hits and splash both. Offline it no-ops on `LobbyNetwork.IsActive`, so the
   training dummy still takes damage as before.

Also: `InstallAvatarComponents` ran once in `Start`, but the slot-Two body registers itself
from ITS `Start`, which may run later. It now retries in `Update` until both avatars are in
place (`_avatarsReady`), so registration order cannot silently break the relay.

### Features added

- **Name entry**: editable field on the lobby root screen, seeded from the machine name and
  pushed into `_net.LocalPlayerName` as it changes. `FocusField` / `ClearFocus` keep exactly
  one text field live; `ClearFocus` runs on every screen change so keys never land in a field
  you have navigated away from. `TypeInto(ref string, maxLength)` is the shared keyboard
  handler (A-Z contiguous in the `Key` enum => offset from `Key.A`, digits via the existing
  `DigitKey` switch, space, dot, backspace; Enter is the caller's business — chat SENDS on
  Enter, the name and address fields just close).
- **Lobby chat**: `MsgChat` on the wire (both directions), `LobbyNetwork.SendChat` /
  `OnChat(sender, text)`, a rolling `_chatLog` (9 lines) painted into a panel on the right
  of the wide lobby screen, input box included. `AppendChatLine` defers its rebuild through
  `_pendingRebuild` because `OnChat` fires from inside `PumpInbound` mid-Update.
- **Scoreboard (hold TAB)**: built into `MatchHud` — it was already in the scene with the
  canvas, font and scaling, so no scene edit was needed. Both players' name / kills / deaths
  / K/D / points, a points-toward-win bar per row, local row tinted. `ScoreManager` gained
  `_deaths` + `GetKdr`; deaths ride `MsgScore` and are flipped on a client alongside kills.

### Gotcha worth remembering

`MatchHud.MakeLabel` anchors children to the parent's TOP edge when the anchor is `(., 1)`,
so `anchoredPosition.y` counts DOWN from the top and a 440-tall panel holds content from
`y=0` to `y=-440`. I nearly "fixed" an overflow that did not exist by misreading this as
centre-relative. Same convention as `LobbyUI.AddLabel` (which is centre-x, top-y).

## THE REAL REASON players could not see each other — NetMatchBootstrap never ran

After all the avatar-relay fixes, the user STILL could not see the other player. The runtime
log had `[PlayerTwoDummy] Registered as player two` but **zero** occurrences of
`[NetMatchBootstrap] Installed NetMatchSync` — anywhere.

**Root cause: `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` fires EXACTLY ONCE, after the
FIRST scene.** The game starts in `MainMenu` (scene 0 in `EditorBuildSettings.asset`), where
`LobbyNetwork.IsActive` is false, so `Install()` returned early. When the host later called
`SceneManager.LoadScene("Manuel")`, that callback did not fire again — Unity only raises
runtime-initialize methods during engine startup, not on scene loads.

So NetMatchSync was never added, which meant no `NetPlayer` on the local body (transforms
never left the machine) and no `NetProxyPlayer` on slot Two (the other body never moved). All
the relay fixes from earlier were correct but unreachable.

**Fix:** `NetMatchBootstrap` now has a `BeforeSceneLoad` hook that subscribes to
`SceneManager.sceneLoaded` once, early. Every load after the first goes through the same
`Install(Scene)`, which is idempotent (skips a root already carrying a NetMatchSync) so the
menu is harmless. The original `AfterSceneLoad` hook stays, for the launch-straight-into-the-
match case. The scene's `[Managers]` object carries every manager authored, so
`ManagersBootstrap`'s same one-shot pattern does not matter for the match.

### LESSON (apply to any Unity bootstrap here)
`RuntimeInitializeOnLoadMethod` = "once at startup". `AfterSceneLoad` means "after the FIRST
scene", not "after each scene". Anything that must react to a scene loaded later by
`SceneManager.LoadScene` has to subscribe to `SceneManager.sceneLoaded` — that one does fire
per load. Verify with the runtime log: a `[Something] Installed` marker that never appears
means the hook never ran, no matter how correct the code inside it looks.

## Valorant arsenal — all 20 weapons authored, firing modes + falloff + hit zones

`Tools/verify_scripts.py` passes (101 assertions) throughout.

**`WeaponDefinition` gained a Gun block**: `FireMode` (Semi/Auto/Burst), `burstCount` /
`burstInterval`, `pelletsPerShot` + `pelletSpread`, per-weapon `headshotMultiplier` /
`legshotMultiplier`, stepped damage falloff (`falloffStart`/`falloffMid`/`falloffEnd` +
two ratios; `falloffStart <= 0` means flat), and `AltFire` (None/Burst/TightSpread/
HeavySwing) with its own damage and windup. `delay` is the reciprocal of rps.

**`WeaponUser` rewrite**: Auto reads the held button, Semi/Burst read the edge. A burst is
its own state machine (`_burstRemaining` / `_burstNextAt`) on a faster clock than `delay`,
and a dry magazine aborts it mid-stream. Pellets fire one `SphereCast` each through
`ConeDirection` (sqrt radius so density is uniform across the disc). Damage is
`damage * DamageRatioAtDistance(hit.distance) * ZoneMultiplier`, and the zone comes from the
hit point's HEIGHT inside `collider.bounds` — no extra colliders on the bodies, works
identically on the network proxy, and the shooter computes the final amount before relaying
so both machines agree. Reload now cancels a swing/burst in progress.

**Two fixes beyond the arsenal:**
- `WeaponManager.ResetPurchases` + `OnManagerAwake` now `EquipDefault()` — sidearm first,
  knife as last resort — so nobody stands in a round with `EquippedIndex == -1` and nothing
  to fire.
- `WeaponUser.Update` early-returns on `LoadoutUI.IsOpenNow` (new static). `Update` runs even
  with `timeScale == 0`, so clicking shop rows used to fire the gun you were selling.

**Assets**: 20 `.asset` files hand-authored in `Assets/Data/Manuel/Weapons/` (folder metas
generated too) and wired into the scene's `WeaponManager` catalogue (was `catalog: []`,
now 20 GUID entries). Sources: valocheck + gamegrids (2026-09) agreed on price/mag/fire rate;
the wiki (wiki.playvalorant.com) rate-limited mid-session, so conflicts were resolved by
majority. Patch **12.09 (May 2026) nerfed shotguns** — Bucky per-pellet is 34/17 now, not
40/20 — and every shotgun fires **15 pellets**; the damage numbers in the assets are
per-pellet. Outlaw (2400, 140 body) and Bandit (600, 39 body) are the post-2024 additions.

**Known simplifications, none blocking**: no recoil/bloom or spray pattern, no movement
inaccuracy (belongs with the movement task), no Ares/Odin spin-up, falloff is proportional
across hit zones rather than per-zone, and the inventory is still one carried weapon at a
time — no primary + sidearm + knife slots or weapon-switch keys.

### PYTHON GOTCHA: `%`-formatting does not escape braces
Writing Unity YAML from Python with a `"...%s..."` template: `{{fileID: 0}}` stays literally
`{{fileID: 0}}` — `{{` escaping is `.format()`/f-string syntax, not `%` syntax. The assets
were written with doubled braces and only caught by inspection. Parse every generated YAML
file before trusting it.

## Valorant movement (Task #23) — slide cut, values retuned

The old `PlayerController` was an arena-fighter feel: slide on Shift, walk 5.0, crouch 1.15,
deceleration 20. Valorant's gunplay movement is the opposite — brisk, repeatable peaks and
near-instant stops — so the slide went and the numbers moved.

- **Slide deleted entirely** (5 fields, `IsSliding`, `_slidePressed`/`_slideTimer`/
  `_slideDirection`, the start/steer branches, the Shift read). Nothing outside
  `PlayerController` referenced it; the camera-feel layer's `!_isSliding` guard went too.
- **Retuned**: `moveSpeed` 5.4 (knife-out speed), `crouchSpeed` 3.0 (~55%), `jumpHeight` 1.0,
  `acceleration` 16, `deceleration` 90 (a full-speed stop in ~0.06s — that is the Valorant
  "stop and shoot" feel), `airControl` 0.45 (a jump can be curved, not reversed),
  `crouchTransitionSpeed` 14.
- Kept the camera-feel layer (bob / strafe lean / landing dip / eased crouch eye height)
  intact on top of the new numbers, and kept the "no jump while crouched" rule — Valorant
  keeps crouch and jump as separate options.
- Scene YAML updated by hand to match (slide keys removed, new values written), and the
  `MatchPreset` superSpeed tooltip no longer mentions stacking a slide.

**Deliberately NOT added:** Shift-walk (Valorant's silent slow walk). There is no footstep
audio subscriber for `OnFootstep` and no movement-inaccuracy model, so it would be a key
that does nothing. Same reason per-weapon move speed (knife 5.4 / rifle ~4.6 / heavy slower)
was left out — `WeaponDefinition` has no speed field and authoring it into 20 assets is its
own task. Both are candidate follow-ups.

`verify_scripts.py`: 129 assertions, all pass. The CS0246 from the earlier session
(`SpikeManager` missing `using ProjectLEA.Manuel.Net;`) is still fixed, and check 6b now
catches that whole class of missing-using bug. Unity's log shows no `error CS`.
