## The ground slab was 50 cm too low

`RelayGround` had `GroundPosition = (0, -1, 0)` with a comment claiming the top lands at
y = 0. A Unity cube is 1 unit **centred on its own origin**, so a Y scale of 1 at centre -1 puts
the top face at **-0.5** — exactly the bug the function exists to fix (the placeholder's top was
at -0.51). The player would have spawned standing in a hole, and the imported walls would float
half a metre above the slab.

Fixed to `GroundPosition = (0, -0.5, 0)`, so the top face is at 0. Cross-checked against the
scene's own tuning before trusting it:

- `CharacterController` height 2.0, **center y = 0** -> the capsule spans +/- 1 about the Player
  origin. `MoveTo("Player", SpawnOne, 1.02f)` therefore puts the capsule *bottom* at 0.02, and
  `SpawnManager.spawnHeight = 1.1` does the same via `+ Vector3.up * 1.1`. Both assume the floor
  is at 0 and neither works against a floor at -0.5.
- `PlayerTwoDummy`'s capsule (centre 0, height 1.8) at `MoveTo(..., 1f)` -> bottom at 0.1. Same
  assumption.

The `Debug.Log` in `RelayGround` now computes and prints the actual top face instead of
asserting it, because asserting it is what hid the error.

### Beans: exported, orientation solved, bake written (23:30 onward)

`bean.blend` (1.7921 m) and `gentlemanbean.blend` (2.0941 m, adds hat + monocle) are now
`Assets/Models/Manuel/Characters/{Bean,GentlemanBean}.fbx`, each carrying all five clips
(`Idle`, `Walk`, `Crouch`, `Crouch_Idle`, `Crouch_Walk`, 24 fps). Verified with a hand-written
binary-FBX parser (`Tools/fbx_nodes.py`) rather than by trusting the export dialog.

**Blender 5.1 FBX orientation, settled empirically** (this was the last thing in doubt): the
axis conversion goes on the ROOT node, not the vertices, so a vertex dump says nothing. Every
top-level object in the exported file carries `Lcl Rotation: (-90, 0, 0)`, which maps
Blender `(x, y, z)` -> Unity `(x, z, -y)`. The bean's eyes sit at Blender Y ~ -0.4, i.e. the
bean faces Blender -Y, i.e. **Unity +Z** - it arrives upright and facing forward with no
corrective rotation needed. The rig root is already between the feet at the origin, so the
bake keeps that pivot (centring the mesh on the capsule axis would slide the bean off its own
feet).

**Binary FBX format notes discovered while parsing** (worth keeping, they cost an hour):
header magic is `Kaydara FBX Binary` + two spaces + NUL (not the single space the docs imply);
Blender writes properties WITHOUT names (one-byte type code then data, verified against the
recorded property-list length: an `I`+int32 is exactly 5 bytes); `Properties70` children are
nodes literally named `P` whose properties are the field list; Python `struct` `l` is 4 bytes
on Windows but FBX `l` arrays are 8, so use `q`; the file has no wrapping root -
`Definitions/Objects/Connections/Takes` are sibling top-level nodes.

**Bake pipeline written** (`ContentSetup.cs`, marker `ContentSetup.done` DELETED so it fires on
the next reload): per bean -> ensure Generic rig (default import is no rig = no avatar) ->
measure `SkinnedMeshRenderer.localBounds` (the bean has no MeshFilters) -> scale to 1.8 m,
lift by the mesh's below-origin dip -> strip colliders -> Animator with a per-bean controller
(two 1D blend trees on `Speed`, `Crouch` bool between them, clips looked up by name with and
without the `BeanRig|` prefix) -> `BeanAnimation` component -> `SaveAsPrefabAsset`. Then the
player's body is replaced and placed at the capsule BOTTOM (the bean stands on its origin, the
capsule is centred on the player's, so it must drop or it floats a metre), `PlayerTwoDummy` is
re-pointed with its capsule re-centred to `(0, 0.9, 0)` and the body dropped by the same
amount, tinting is now opt-out (default off) so the bean keeps its skin/eye/pupil materials,
and the human assets (`PlayerGuy.glb`, `PlayerGuy.prefab`) are deleted - the scene's only
references are the Player's `BodyPlaceholder` (destroyed in the swap) and the dummy's
`bodyPrefab` (re-pointed).

New runtime script `Assets/Scripts/Manuel/BeanAnimation.cs` drives the animator from its OWN
measured horizontal delta (works identically for the local player, the network proxy and the
dummy, no wiring), crouches only when a `PlayerController` is in the parent chain, clamps the
speed so a respawn teleport does not read as a sprint.
